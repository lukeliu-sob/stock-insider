## Driver

In a live three-turn session on the owner's store (`/report 1211.HK` included), the post-check marked 17 numbers `[?]`. Nearly all of them were correct, and they set off the "three answers in a row" warning, which told the owner to check the data although the data was fine. The misreadings fall into six claim-side classes:

| Class | Live example | What the checker did |
|---|---|---|
| `inline_list` | "Open 74.6 · High 74.9 · Low 73.3 · Close 73.9" | read 74.9 as the open: a middle dot does not end the "Open" cue |
| `table_count` | a "Max drawdown" row whose window cell says "259 sessions" | read 259 as the row's metric instead of the count its noun names |
| `reference` | "see §2", "(1) confirm the listing ... (2) a sync run" | took section and list numbers for claims |
| `quoted_title` | a headline in backticks, or verbatim in a table cell, that contains "50%", "3", "2026-2030" or "100+" | required straight quotes, so the title's digits were claims |
| `sentiment_component` | "polarity -0.768 alongside neg 0.224 and neu 0.776" | let the earlier "polarity" cue govern, although each number is written right after its own key name |
| `decline_sign` | "fell 2.73% over the last 20 sessions" | attached the decline's sign to "20" and left 2.73 unmatched against the signed change -2.73 |

## Scope

`agent/guardrail_claims.py` only (safety-critical prefix). These rules are claim-side only:

- **inline_list**: a middle dot (·), a bullet (•) and a vertical bar in prose end a field cue's reach, as a comma or a semicolon already does.
- **table_count**: inside a table cell, a count noun right after a number ("259 sessions") types it, before the row's metric label does.
- **reference**: a number right after a section sign (§2) or a pilcrow, and a list enumerator — "(2)" or "2)" opening a list item, or "(2)" right after a sentence or clause boundary and before a word — is an identifier, not a claim.
- **quoted_title**: text in backticks counts as quoted, as straight and curly quotes already do. A table cell whose whole text (trimmed, with surrounding quotes or backticks removed) equals a string value in the ledger is a quotation of that value.
- **sentiment_component**: a ledger key name written immediately before a number ("neg 0.224") types the number by that key, before an earlier cue in the clause.
- **decline_sign**: a decline word gives its sign to the next percent-valued number only, never to a count. A decline-signed percent also matches a negative ledger value of the same magnitude.

Not changed: the evidence side, the declared typing, subject resolution, P3 (digits in titles and URLs verify only when quoted; the backtick and table-cell forms above are quotations), the v1 fallback, `shared/`, the registry. A number paraphrased from a tool's prose text without quotes ("need 5+") stays unverified under P3. The owner decides on that separately.
