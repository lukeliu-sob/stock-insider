## Driver

- **DE-08**: a gap's empty-attempt counter and the gap-repair budget share (half the daily cap) both counted per `sync` run, not per calendar day. Three quick re-runs during a vendor outage could close a fillable gap as `no-data` after three same-day attempts; same-day repeated runs could each claim a fresh half-cap share, letting gap-repair consume far more than half the day's calls in total.
- **DE-11**: migration v6 demoted pre-ADR-005-Am2 secondary-exchange rows to `verified = 0`, but a symbol already ACTIVE on the watchlist stays active and keeps syncing; no report listed such entries.

## Fix

**DE-08**: both counters now use the same lazy-reset-by-date mechanism the real call budget (`CallBudget`) already implements.
- `CallBudget` gains an optional `track` parameter (default unchanged); `sync.py` creates a second instance under track `gap-repair-daily` and reads/writes it instead of a per-run local variable, so the gap-repair share persists across same-day runs.
- Migration v7 adds `sync_gaps.empty_attempts_date`; an empty-attempt only increments `empty_attempts` the first time it is seen on a given calendar day - a gap needs three *different* days of empty results to close as `no-data`, not three quick same-day re-runs.
- The deferral message changed from "(N calls/run)" to "(N calls/day)" (no test hardcoded the old wording).

**DE-11**: `WatchlistService.list()` selects `symbols.verified` alongside the existing columns (visibility only - no behavior change to what stays active or synced). `watch list` (CLI) prints `[unverified resolution]` for such a row; the `watchlist.list` agent tool's description is updated to mention verification status (same dict, no new registry enforcement).
