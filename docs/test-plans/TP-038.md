## Driver

DE-18: `data/ingest/http.stdlib_fetch`, the vendor transport for EODHD and GDELT, validates the first URL against the egress whitelist, but `urllib.request.urlopen` follows redirects on its own, so a redirect to another host is fetched without a second check (SEC-003). The TP-035 page seam already re-validates every hop through `_EgressCheckedRedirects`.

## Scope

- `data/ingest/http.py`, `stdlib_fetch`: open through `urllib.request.build_opener(_EgressCheckedRedirects)`, the handler the page seam uses, so every redirect target passes `validate_egress_url` before it is followed.
- A refused redirect becomes `TransportError("egress", ...)`, a new transport kind. Agent decision, recorded for owner review: the vendor callers handle `TransportError` per item or per query (market and fundamentals per item, GDELT and EODHD news per query). A raw `EgressViolationError` from a redirect would instead abort the whole news track at the sync isolation boundary. A vendor redirect is runtime vendor behavior, not a configuration error, so it fails that item visibly and the run continues (INV-003). The first-URL check is unchanged: it still raises `EgressViolationError` before any request, because a wrong first URL is a code or configuration error.
- Not changed: `shared/egress.py` (whitelist and matching rule), the page seam, every caller, the call budget, retries (none).

## Planned tests

New file `test/offline/test_tp038_vendor_redirects.py`. The tests patch `build_opener` or drive the handler directly; no socket is opened.

| Test | Verifies | Kind |
|---|---|---|
| `test_vendor_fetch_uses_the_egress_checked_opener` | `stdlib_fetch` opens through an opener built with `_EgressCheckedRedirects` | positive |
| `test_redirect_off_the_whitelist_becomes_transport_egress` | a redirect to a host outside the whitelist raises `TransportError` with kind `egress`, and the off-whitelist URL is never opened | negative/adversarial (R7) |
| `test_redirect_to_plain_http_is_refused` | a redirect from HTTPS to plain HTTP on a whitelisted host is refused the same way | negative/adversarial (R7) |
| `test_redirect_within_the_whitelist_is_followed` | a redirect to another whitelisted HTTPS URL is followed and its body returned | positive |
| `test_first_url_violation_still_raises_before_any_request` | an off-whitelist first URL raises `EgressViolationError` and no opener is built | negative |
| `test_market_sync_reports_an_egress_item_and_continues` | in a sync run whose transport raises `TransportError("egress")` for one symbol, that item is reported failed with the reason, and the other symbols still sync | negative (INV-003) |

Mutation checks: `stdlib_fetch` back on `urlopen` (the opener test and the off-whitelist test fail); the egress conversion removed (the transport-kind test fails).
