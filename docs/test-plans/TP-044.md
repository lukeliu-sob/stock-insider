## Driver

In the live session the model wrote "Annualized volatility 0.32758162495489135 (fraction)" and "Max drawdown -0.3850954177214963". It was obeying identity v7: "render tool-returned numerics exactly as received — no rounding, ... display the fraction". That rule predates ADR-008. Since the owner's decision of 2026-10-02, the post-check accepts rounding to the written precision and a fraction written as a percent. The prompt still forbids both, so every answer carries 16-digit floats.

## Scope

- `prompts/identity.md`, v7 to v8. The "Numbers render as returned" rule keeps its name and place and now allows two readability changes:
  - a fraction may be written as a percent with two decimals (0.32758162 as 32.76%);
  - a long decimal may be shortened (0.32758162 as 0.3276).
  
  Prices, volumes, counts and dates stay exactly as returned. A value is never given more precision, another sign or another quantity. `market.performance`'s `change_pct` is already a percent, so -4.8828 reads -4.88%. The version history comment records the change.
- Not changed: the post-check, the tools, the data. Evidence values stay full precision, and only the rendering changes.

## Note (2026-11-03, after a live run on a copy of the owner's store)

A live session on v8 rounded most values as intended, but one table still printed the raw fraction beside its percent ("0.3717513206578831 (37.18%)"). The rule now says to use one form per value, with the percent replacing the fraction. The version stays at v8, because the change is unmerged and part of the same plan. The prompt test pins the added sentence.
