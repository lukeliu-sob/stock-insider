## Scope

`data/ingest` becomes real (market path only; fundamentals TP-010,
news TP-011). **In scope**:

1. **HTTP transport seam** (`data/ingest/http.py`): stdlib urllib,
   egress-gated, fixed timeout; responses classified into
   ok / rate-limited (HTTP 402 — EODHD's exhausted-plan signal) /
   http-error / malformed. 402 produces the explicit "capacity is
   bought, never worked around" report (ADR-002) — zero retries.
2. **Market adapter** (`data/ingest/market.py`): `fetch_eod(symbol,
   from, to)` against `https://eodhd.com/api/eod/{symbol}` (host
   corrected by BD-010; live-probed this round: rows are
   `date/open/high/low/close/adjusted_close/volume`). Rows are
   schema-validated before storage; **any invalid row fails the whole
   symbol batch** (transactional, fail-closed — no partial writes, no
   silent row skips).
3. **Schema migration v2** (the migration machinery's first real
   forward-only run): `market_bars` gains `adjusted_close REAL`
   (nullable). Canonical storage: raw OHLC + adjusted_close, `adjusted`
   flag marks the series semantics. Rationale: preserves data
   fidelity; `data/compute` (TP-013) picks the series per indicator.
4. **Call-budget guard** (`data/ingest/budget.py`): default **20
   API calls/day** (free tier), overridable via `EODHD_DAILY_CALLS`
   (tests / future paid tier). Counter lives in `sync_state` (track
   `eodhd-budget`), resets lazily on date change. Before every call:
   check-and-spend. On exhaustion: the plan's remaining items are
   reported explicitly as deferred (INV-003), never silently skipped.
5. **Trading calendar** (`data/ingest/calendar.py`): derived from the
   benchmark indices' own bars (D3 decision): HK trading days =
   dates present in `HSI.INDX`; US = `GSPC.INDX`. No extra API surface;
   the completeness rule and the calendar are self-consistent by
   construction.
6. **Sync service** (`data/ingest/sync.py`): plan = (a) indices
   missing bars -> 5y backfill, (b) `sync_gaps` queue entries (the
   `watch add` enqueues), (c) active watchlist incremental
   (cursor -> today), (d) completeness pass comparing stored dates vs
   calendar -> enqueue newly found gaps; execute in that priority
   order under the budget; per-symbol transactional upsert + cursor
   update; final report: per-symbol ok/fail with last bar date,
   budget used/remaining, deferred items.
7. **Surfaces**: CLI `sync` real; REPL `/sync` and registry tools
   `sync.run` (WRITE; the slash handler passes `user_confirmed: true`
   — typing the command is the confirmation) and `sync.status`
   (READ).
8. **Currency**: static per-exchange map (HKD / USD); indices stored
   as `POINTS` (benchmarks are dimensionless).

**Not in scope**: fundamentals, news, `get_quote`/`info` (TP-010),
bulk universe (FR-018, Could), FX ingestion.

## Negative tests (mandatory, R7)

Malformed-row batch failure; transport error; budget exhaustion with
explicit deferral; 402 single-shot policy; write-gate block on
sync.run.

## Boundary cases (R8)

Budget: exactly 20 and the 21st call. Completeness: holiday dates
excluded from expectation (boundary of the calendar rule).

## Fit-criteria mapping

- **FR-001 (a)**: deleted-bar refetch test asserts the exact deleted
  date returns; (b) post-sync completeness equals calendar count with
  tolerance 0; gap detection is the completeness pass.
- **QA-003**: the completeness metric is computed and stored in the
  sync report (`stored / expected` per symbol).
- **INV-003**: every failure mode above produces an explicit
  per-symbol report; zero substitute values (no fabricated bars, no
  stale-as-fresh — every stored bar carries its own date).
