## Driver

DE-15 (field/subject typing in `agent/guardrail_claims.py` is a hand-maintained cue vocabulary guessing at tool-result meaning) and DE-16 (company names resolve only when the session ledger happens to carry one) are both named in ADR-008 as deferred to "phase 3." ADR-005 Amendment 4 records the wire-format decision this plan implements: `ToolSpec` gains `result_fields`/`result_discriminators` (a `FieldSemantics` declaration per field, direct or discriminator-tagged), and `official_name` reaches the tools DE-16 names. See that amendment for the alternatives considered (full jsonschema/pydantic adoption, rejected as oversized) and the residual risk this plan does not close (a company entirely absent from a session's ledger still cannot be recognized as a subject).

## Scope, staged (TP-017 PR-1..3b precedent: one plan, several PRs)

- **Stage 1 (this PR)**: the contract only. `shared/tools.py` gains `FieldSemantics` and the two new `ToolSpec` fields, defaulting to empty - every existing `ToolSpec` is unaffected, nothing declares anything yet, nothing consumes it. Zero behavior change; purely additive.
- **Stage 2**: `agent/guardrail_claims.py`'s evidence-typing (`_evidence_field`, `index_evidence`) reads a tool's declared `result_fields`/`result_discriminators` when present, falling back to the current heuristic vocabulary otherwise - the cutover is per-tool, not a single flag day. Requires a way for the guardrail to look up a tool's `ToolSpec` by name (`agent/guardrail_claims.py -> agent/registry` is an allowed edge per AGENTS.md's dependency map; exact accessor shape decided when this stage is scoped).
- **Stage 3**: declare `result_fields`/`result_discriminators` for the data modules currently read by the heuristic vocabulary, in small batches (`market.py` + `fundamentals.py`; then `indicators.py`; then `news.py` + `eodnews.py` + `sync.py` + `watchlist.py` + `resolver.py` + the `store/__init__.py` facade) - each batch independently testable, each batch's tools stop relying on the fallback.
- **Stage 4 (DE-16)**: `official_name` added to `market.quote`, `market.indicators`, `fundamentals.summary`, `news.recent`, `news.search` (joining the symbols table `resolver.py` already populates); `agent/guardrail_claims.py`'s subject resolution reads it as a fourth source alongside tickers, bare codes, and the first word of an existing `official_name`.
- **Stage 5**: P6 held-out remeasurement (a fresh battery, not E-010 reused, since the typing mechanism itself changed - same discipline TP-024 used), recorded as ADR-008's own phase-3 amendment once stages 2-4 are in.

Each stage amends this plan's "Planned tests" and "Regression scope" before its own implementation commit (GOV-006); stage 1 below is fully scoped now.

## Stage 2 (amendment, 2026-10-04): declared typing consumed by the guardrail

Approval: owner, in-session answer on 2026-10-04 to the stage-2 scope question: "approve as scoped (recommended)". This amendment is committed before the code, per GOV-006. Linked ADR: ADR-005 Amendment 4.

### Scope

- `agent/guardrail_claims.py`: `index_evidence(snapshot_values, specs=None)` takes an optional mapping from dotted tool name to `ToolSpec`. The `Evidence` object carries that mapping. `_add_entry` asks a new helper, `_declared_field(evidence, tool, key, siblings)`, first. When the helper returns nothing, the existing `_evidence_field` heuristic runs unchanged. The heuristic is the per-tool fallback, so the cutover is per tool.
- Declared lookup, per numeric leaf:
  1. A direct key: `result_fields[key]`, matched exactly.
  2. A discriminator row: for a leaf named `value`, `result_discriminators[d][siblings[d]]` for the discriminator field `d` whose sibling value selects an entry (ADR-005 Am4, `{metric, value}` rows).
  A direct key wins over a discriminator. Only `FieldSemantics.field` is consumed here. `unit` and `subject_bearing` are not consumed: `unit` waits for a later stage, and `subject_bearing` belongs to stage 4.
- Threading: `run_postcheck`, `postcheck_numbers`, `guardrail_claims.check` and `scan_claims` each gain an optional `specs` keyword, default `None`, passed through unchanged. `agent/loop.py` passes `{spec.name: spec for spec in self._registry.list_tools()}` at both post-check call sites. No new accessor is added: `Registry.list_tools()` exists. The snapshot key's tool segment is the dotted spec name (`loop.py`: `name = wire_map.get(raw_name, raw_name)`, key `f"{turn_id}/{name}#{call_seq}"`), so the lookup matches.
- `shared/` and `Registry.execute()` are not changed (ADR-005 Am4).
- No tool declares fields in this stage. The change is behavior-neutral until stage 3 declares them.

## Stage 4 (amendment, 2026-10-27): `official_name` on subject-bearing results (DE-16, in-ledger class)

Approval: owner, in-session answer on 2026-10-27: approved as drafted. Scope decisions taken the same day before this draft, all as recommended: names on results only; verified names only; the guardrail reads a news row's symbol bucket; `official_name` is not declared `subject_bearing`; the postposed-subject false flags the names expose are pinned and measured in stage 5, not fixed here. This amendment is committed before the code, per GOV-006. Linked ADR: ADR-005 Amendment 4.

### Findings that shaped the scope

- The guardrail already turns names into subjects: `_collect_names` maps the first word of an `official_name` beside a `symbol` or `canonical_symbol` in the ledger to that symbol, keeping only unambiguous words. Names on the five tools reach that path with no new matching code.
- DE-16's five waived E-010 claims fall into two classes. H020 (two claims) and H022 name companies that are in the ledger, but whose results carry no name: names on results close this class. H047 (two claims) names companies absent from an Apple-only ledger. Recognizing them would need names from outside the session snapshot, which INV-001 checks against and replay depends on. That is ADR-005 Am4's recorded residual; it stays open.
- A prototype of this scope, run on name-bearing copies of the E-010 ledgers (E-010 is not an independent measurement for this change), gave held-out recall 0.975 (escapes: H047 x2), up from 0.938, and precision 0.976, down from 0.988. Two new false flags, H021 "18,982,584" and H030 "15.23", share one class: the subject follows the number ("against 18,982,584 for BYD"), while `_resolve_subject` prefers the mention before it. Without names these claims could verify against any subject. The full offline suite was unchanged (745 passed), and the existing E-010 tests are unaffected because their ledgers carry no names.

### Scope

## Stage 5 (amendment, 2026-10-27): E-013, an independent held-out remeasurement of phase 3

Approval: owner, in-session answer on 2026-10-27: approved as drafted, including spawning the separate author agent. Scope decisions taken the same day before this draft, all as recommended: a separately briefed subagent authors the battery; stage 5 measures and pins, and any follow-up is a new owner decision under a new plan; labels get a mechanical consistency check whose disagreements go to the owner, with the battery file left unedited. This amendment is committed before any stage-5 artifact, per GOV-006. Linked ADRs: ADR-008 (its phase-3 amendment records the result), ADR-005 Amendment 4.

### Purpose

Stages 2-4 changed the evidence typing (declared fields) and the subject sources (names on results). E-010 was looked at while both were built, so it is no longer an independent instrument (TP-024 Amendment 1, stage 4 result). E-013 is a fresh held-out battery, written before the measurement by an author who has not seen the engine. Stage 5 changes no engine code: the engine is frozen at the stage-4 tree, and its source hash is recorded before the battery is evaluated.

### Steps, in commit order

1. **Frozen ledgers** (`test/offline/fixtures/e013_ledgers.yaml`): session ledgers produced by the real tools over a seeded fixture store, so every shape is exactly what the post-check sees in production, with stage-3 declarations and stage-4 names in place. A generator in the test file rebuilds them, and a drift test asserts the frozen file equals the rebuilt one. Planned ledgers:
   - `hk_pair`: `market.quote` and `market.indicators` for 0700.HK and 1211.HK, `news.recent` for 0700.HK.
   - `us_pair`: `market.quote`, `market.indicators` and `fundamentals.summary` for AAPL.US and TGT.US. Target Corp's first name word is a common English word, for the first-word collision class.
   - `apple_only`: AAPL.US quote and indicators only, for companies absent from the ledger.
   - `session`: `watchlist.list`, `sync.status`, `news.search` with symbol and macro buckets.
   - `unverified`: a quote for a symbol whose name is unverified (null), so its company name has no ledger source.
2. **Brief and battery** (`test/offline/fixtures/e013_heldout.yaml`):
   - Author: a subagent with its own context, briefed not to read `src/`, `test/` (other than the ledger file) or `docs/test-plans/`. Its brief is the frozen ledgers, the claim classes below, the label format and the counts. The brief is committed in the same commit as the battery (`test/offline/fixtures/e013_brief.md`).
   - Classes: every TP-024 Appendix A class that has evidence in the ledgers; name misattribution between in-ledger companies; a subject written after its number ("for BYD", "at Apple"); a company absent from the ledger; a company whose name is unverified; a common-word first name ("Target") used as an ordinary word; tables; over-precise and fabricated values.
   - Counts: at least 80 claims, at least 35 of them wrong, and at least 5 claims in each of the last six classes above.
   - The file is committed unedited, before the measurement run.
3. **Label check**: before the run, a script checks each label mechanically against the ledger values, without the engine. A claim labeled correct must have a matching value for its stated subject and field at its written precision. A claim labeled wrong must not. Disagreements are reported to the owner, who rules on each. Rulings are recorded as an overlay in the test file (`LABEL_RULINGS`) and in this plan; the battery file is never edited.
4. **Run and record**: one run on the frozen engine. Recorded per class: precision (the share of correct claims left unmarked) and recall (the share of wrong claims marked), plus the list of escapes and false flags. E-013 goes into `docs/architecture/evaluation-logbook.md`, and ADR-008 gains its phase-3 amendment (stages 2-4 consumption plus the E-013 result). DE-15 and DE-16 statuses are updated from the result.
