## Scope

**Changes**: `pyproject.toml` (project metadata, dependency set, tool configuration, console entry point); package skeleton under `src/stockinsider/` — package root, `agent/` shell, `data/` shell, `cli/` shell with `app.py` registering all nine FR-013 subcommands as **explicit-failure stubs** (English error naming the target requirement, non-zero exit — INV-003 semantics: refuse to pretend success); `test/offline/test_cli_surface.py`; CI `[DE-05]` guard removal for the `quality` and `regression` jobs (both install the package and run unconditionally); `CODEOWNERS` placeholder `@team-owner` → real owner handle; debt-register DE-05 partial repayment; AI-use log.

**Explicitly does not change**: any command's real behavior (all nine are stubs); the REPL mode (FR-013 "bare invocation starts a REPL" — deferred to the agent-runtime TP); `shared/` and `agent/registry/` module creation — **deferred out of this plan by the governance gate ruling**: they are safety-critical paths whose every change requires a linked ADR (guard G2), so they land with their feature test plans and ADRs instead of casually at scaffolding time; the registry; all other governance artifacts except debt-register/AI-log bookkeeping.

## Negative tests (mandatory, R7)

`test_stub_commands_fail_explicitly`: invoking any of the nine subcommands must fail **loudly and honestly** — non-zero exit code, output containing "not implemented" and the subcommand's target REQ ID. The adversarial intent: any future change that turns a stub into fake success (exit 0 with no real behavior) turns this test red.

## Boundary cases (R8, for threshold rules)

None — this change introduces no thresholds (no budgets, caps, or QA thresholds touched).

## Fit-criteria mapping

- **FR-013** fit criterion (subcommand surface): `test_help_lists_subcommands` asserts the full nine-name set verbatim from FR-013's statement. The REPL half of the criterion is **out of scope** (see Scope) — partial coverage acknowledged; the agent-runtime TP completes it.
- **INV-003** (fail-safe, stub subset): `test_stub_commands_fail_explicitly` asserts explicit failure with a truthful English message and non-zero exit; no silent fallback, no fabricated output.
