## Driver

The owner finds the REPL display too bare and asked for a terminal UI in
the style of Claude Code (2026-10-01). Decisions taken in session:
inline style; prompt_toolkit accepted as a dependency; placement
`agent/tui/`; opt-in first; answers render as Markdown; Unicode chrome
allowed inside the UI; the UI is a new requirement (REQ-SI-FR-026).
Design and its rationale: ADR-007.

## Behavior under test

- `stockinsider --ui tui` (also `analyze --ui tui`, `resume --ui tui`,
  or `STOCKINSIDER_UI=tui`) runs the REPL with a framed input, a slash
  completion menu, a status line (session, profile, model, tokens,
  verdict, watchlist size, call budget) and an activity indicator during
  turns. Answers appear only after the post-check, rendered as Markdown
  when render fidelity holds and as literal text otherwise.
- A write proposed by the model becomes a choice prompt after the turn:
  decline is the default; an explicit accept submits `confirm <token>`
  through the existing confirmation path.
- Ctrl+C clears a non-empty input; on an empty prompt the first press
  shows a hint and a second press within 2 s exits. Ctrl+D and `/exit`
  exit. Ctrl+C during a turn interrupts it. Every exit closes the session
  and leaves the resume hint in the scrollback.
- Without the opt-in, or without an interactive terminal, the plain
  REPL runs with byte-identical output (the latter with an explicit
  notice on stderr).

## Negative tests (mandatory, R7)

- Display (INV-001): `test_no_model_text_before_verdict`,
  `test_quarantined_original_never_displayed`,
  `test_regenerated_answer_displayed_once`, and the two fidelity
  fallbacks.
- Consent (INV-004): the five confirmation tests and
  `test_sub_prompt_cancel_is_safe`.
- Explicit failure (INV-003): the three fallback tests,
  `test_exception_closes_bound_session`, and the `?` rendering of
  unknown counters.
- Surface: `--ui fancy` is rejected; Ctrl+C with text submits nothing.

## Boundary cases (R8)

- Double Ctrl+C window (2 s, injected clock): a second press at 1.9 s
  exits; at 2.1 s it shows the hint again.
- Fidelity: `1. a` / `2. b` keeps Markdown; `1. a` / `5. b` falls back;
  an answer whose only change is one digit falls back.
- Terminal detection: stdin and stdout both terminals selects the UI;
  either one piped selects plain.

## Fit-criteria mapping

REQ-SI-FR-026:

- (a) completion and dispatch share one table:
  `test_completion_equals_command_table`,
  `test_command_table_matches_dispatch`;
- (b) no assistant text before the verdict, quarantined originals never
  shown: `test_no_model_text_before_verdict`,
  `test_quarantined_original_never_displayed`,
  `test_regenerated_answer_displayed_once`;
- (c) digit multisets on screen equal the record:
  `test_turn_end_to_end` plus the four fidelity tests;
- (d) writes need an explicit accept: the five confirmation tests and
  `test_sub_prompt_cancel_is_safe`;
- (e) plain and non-interactive runs are unchanged:
  `test_plain_output_byte_identical`,
  `test_tui_without_terminal_falls_back_explicitly`.

FR-013, FR-019, INV-001 and INV-004 keep their fit criteria and suites;
the new tests add the UI surface to them.
