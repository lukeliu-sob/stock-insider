## Driver

DE-14: runtime policy P-17 and memory-design §3 say a turn interrupted before its answer is recorded with status `incomplete` and left out of context reconstruction. The loop recorded nothing: the user message was already appended, no answer followed, and `_history_messages` replayed the dangling question on the next turn. Surfaced by TP-021, whose terminal UI makes Ctrl+C routine.

Kickoff check, recorded so the design is traceable: the remediation plan guessed ADR-007 as the owner. ADR-007 §3 records DE-14 as a gap it does not own. The owners are ADR-001 (context reconstruction; `_history_messages` cites ADR-001 Am1) and ADR-004 (the event schema).

## Fix

1. `shared/events.py`: `EventKind` gains `TURN_INCOMPLETE = "turn-incomplete"` (ADR-004 Amendment 5). Additive; no existing kind or field changes.
2. `agent/loop.py`: `run_turn` becomes a wrapper around the unchanged turn body `_run_turn`. The body records the open turn's id once its user message is appended, and clears it once its answer is appended. If a `KeyboardInterrupt` escapes while a turn is open, the wrapper appends `{"event": "turn-incomplete", "turn": <id>}` and re-raises. A turn that already has its answer is never marked.
3. `agent/loop.py`: `_history_messages` leaves out a turn that has a marker and no assistant message, before the window is applied (ADR-001 Amendment 2). Such a turn does not replay, does not take a window slot, and does not trigger the truncation note.
4. `agent/repl.py`: the session transcript prints one line for the marker, so the record stays visible (ADR-007: screen == record).

## Scope

Explicitly NOT changed: `agent/guardrail*`, `agent/registry*`, the post-check, `prompts/`, the plain-REPL interrupt message (`turn interrupted`), and the golden transcript.

Residuals, recorded and not closed:
- A hard crash (process killed, power loss) runs no handler, so it writes no marker. P-17 names crashes too; covering them needs a reader-side rule, which is a separate decision.
- Turns that end without an answer on other paths keep today's behavior, so their question still replays: the iteration cap (`loop.py`, `error` with `kind: "iteration-cap"`, then return) and a `ProviderError` that escapes the turn. They are not interruptions. The owner decides whether they count as incomplete; the P-17 wording suggests they do.
