## Driver

On 2026-10-02 two live answers about BYD were withheld whole, each for a
single number (`123202178`, a news timestamp written to the
millisecond; `37`, "about 37%" for a volatility of 0.3711553760998695).

A probe of the post-check the same day showed the same rule set both
withholding correct renderings and passing misattributed numbers
(ADR-008, Context).

The owner decided (2026-10-02):

- replace pool membership with typed claim verification;
- accept rounding to any written precision;
- flag unverified numbers instead of withholding the answer.

This plan covers phase 1: the flag semantics, using the current
detector unchanged. The typed engine is phase 2 (TP-024).

## Behavior under test

1. **Detection is unchanged.** `postcheck_numbers` decides which numbers
   are unverified, exactly as before. That includes BD-012 rounding,
   BD-015 percents, enumeration, dates, the TP-020 calendar and the
   OHLCV field check.
2. **Marking.** Each word that holds an unverified number ends with the
   marker `[?]`:
   - The marker goes before trailing punctuation and Markdown emphasis:
     `37%[?],` and `**0.37[?]**`.
   - Every occurrence of an unverified token is marked, so the marking
     is conservative.
   - Removing the markers returns the model's text exactly.
3. **Fail-closed.** If an unverified number cannot be located in the
   text (for example a normalized date form), the answer is withheld as
   before: stored with `post_check: "failed"`, with the degraded
   `data unavailable for:` line.
4. **Display of a flagged answer.**
   - The marked text is shown as the answer, in both front-ends,
     through the answer channel (`stream_sink`). The unmarked deltas
     are never replayed.
   - A notice follows on the progress channel:
     `unverified (not found in this session's tool results; marked [?]): 37, 123202178`.
     A field mismatch is named as such.
   - The footer (`tools · post-check · tokens`) reads
     `post-check: flagged`.
5. **Record.**
   - The assistant-message event stores the marked text as `text`, plus
     `post_check: "flagged"`, `unverified: [...]` and `original` (the
     unmarked text). This keeps screen == record.
   - No `error` event is written for a flagged answer.
6. **History.** A flagged answer is replayed to the model as its marked
   text, plus a harness note:
   `The numbers marked [?] were not verified against tool results: ...; do not restate them as facts.`
   - Records written before this change (`post_check: "failed"`) keep
     today's withheld note.
   - Unverified numbers never enter the evidence ledger.
7. **INV-002 composition.** When the epistemic filter also fires, the
   regeneration runs as today. The final text is then re-verified and
   marked. The violating original is never shown.
8. **Reports (FR-008).**
   - A flagged `/report` is stored with its marked body. Its header
     reads `- unverified numbers: N (marked [?]; not verified by the
     INV-001 post-check)` in place of the "passed the INV-001
     post-check" line.
   - A withheld report is not stored, as today.
9. **Counter.**
   - `PostCheckCounter` no longer returns `abort:number`.
   - Three consecutive answers with unverified numbers produce the
     notice `three answers in a row contained unverified numbers; check
     the data (/sync status) or start a new session`, repeated while the
     streak lasts.
   - INV-002's abort budget is unchanged.
10. **Unchanged surfaces.**
    - The language-policy withhold (GOV-001).
    - The rendering of `/show` and `--ui tui` for old records.
    - The status line shows `post-check flagged` for a flagged last
      answer.
    - The TUI styles the notice as a warning.

## Negative tests (mandatory, R7)

- The zero-tolerance marking battery (`test_every_unverified_occurrence_is_marked`).
- Fail-closed withholding of an unmarkable number.
- No laundering through history or the ledger.
- The language policy still withholds.
- The INV-002 abort still trips.

## Boundary cases (R8)

- Streak notice: two consecutive flagged answers produce nothing; three
  produce the notice; a verified answer in between resets the streak.
- Marking position: a token at the start or end of the text, next to
  punctuation, inside Markdown emphasis or a table cell, and repeated
  in one word.
