QA-002 passing on the title corpus. QA-002 is still `conceptual`: its
verification file `test/offline/test_retrieval.py` does not exist, and
the trace matrix (FR-007 and QA-002 rows) points at that missing file.
Owner decision D10 (`news-rss-body-design.md`, 2026-10-26): option
(a) — implement QA-002 as a feature before TP-035, rather than waive
it.

Embedding provider (owner, 2026-10-26): the embedding role uses
`qwen3.7-text-embedding-flash` (owner-tested, available) at the
OpenAI-compatible base URL
`https://maas.qianwenaiapi.com/compatible-mode/v1` — a different

provides the slot and the defaults.

Scope note: the TP-011a AI-use log entry calls the filter's keep
precision (0.927) "QA-002 calibration evidence". That figure measures
the FR-003 ingestion filter, not retrieval. QA-002 measures what
`news.search` returns for a query; this plan builds that measurement.

## The measurement problem and the chosen shape

Retrieval quality is a property of the real embedding model, while
the offline gate forbids network calls. A fake embedder would make
the gate pass or fail on the fake, measuring nothing. Chosen shape:
**frozen real vectors**.

1. A live generator (`test/live/gen_retrieval_vectors.py`, never
   blocking) embeds the fixture corpus titles and the query texts once
   with the configured embedding model and writes
   `test/offline/fixtures/retrieval_vectors_v1.json`: `model_id`,
   `dims`, `generated_at`, and per text a SHA-256 of the exact
   embedded string plus its vector.
2. The offline suite loads the frozen vectors into a temporary store
   through the production path (`ensure_vec_table`, `insert_vectors`,
   `knn`), so the sqlite-vec KNN path that ADR-003 asks QA-002 to
   cover is the code under test.
3. Staleness fails closed: a corpus or query text whose hash does not
   match its frozen vector, or a text with no vector, fails the suite
   with the offending ids named. It never skips and never re-embeds
   silently (INV-003 discipline applied to the fixture).
4. A change of embedding model is a regeneration, recorded in the
   evaluation logbook with the before/after scores. The suite always
   reports the `model_id` it measured.

## Planned change (single implementation PR after approval)

  known-target queries (FR-007), each with `query`, `target_id` (one
  corpus item that must appear in the top 5), and `relevant_ids` (every
  corpus item judged relevant to the query, the target included).
  Labels are hand-assigned against the corpus and version-controlled;
  a label change is a fixture change in the same change set as its

- `docs/ai-use-log.yaml` entry; evaluation logbook entry with the

## Metrics

Over the query set, with k = 5 and no bucket filter:

- **hit@5** (FR-007 fit criterion): fraction of queries whose
  `target_id` is in the top 5. Gate: >= 0.8.
- **relevance@5** (QA-002 metric): per query, the fraction of the top
  5 hits that are in `relevant_ids`; averaged over queries. Gate:
  >= 0.8.
- Per-query precision is recorded (FR-007: "per-response retrieval
  precision is recorded") in the test report and the logbook entry.

## Planned tests

| Test | Verifies | Kind |
|---|---|---|
| hit@5 >= 0.8 on the query set | FR-007 fit criterion | positive (gate) |
| relevance@5 >= 0.8 on the query set | QA-002 metric | positive (gate) |
| frozen vectors match model_id / dims of the store registration | no silent model mix | negative |
| a corpus text edited after freezing fails with its id named | fixture staleness fails closed | negative |
| a query with no frozen vector fails, never skipped | no silent coverage loss | negative |
| query set has >= 20 queries, every class represented, every target in the corpus | fixture integrity | negative |
| retrieval runs through `ensure_vec_table` / `insert_vectors` / `knn` | ADR-003 KNN-path regression | positive |
| reversed ranking (farthest first) fails both gates | the metric can fail | adversarial |
| random vectors of the same dims fail both gates | the gate is not trivially met | adversarial |
| embedding role resolves `EMBEDDING_API_KEY` from the environment, then `.env` | per-role key | positive |
| embedding host differs from chat host and `EMBEDDING_API_KEY` is unset: explicit error naming the variable, no request sent | no silent default | negative |
| embedding host differs from chat host: the client is never built with `PROVIDER_API_KEY` | chat key never sent to another vendor (SEC-001) | adversarial |
| same host and no `EMBEDDING_API_KEY`: falls back to `PROVIDER_API_KEY` | single-vendor setups keep working | positive |
| `config set` refuses an embedding key in config.json; `--embedding-api-key` writes `.env` only; display masks it | secret handling (SEC-001) | negative |

Mutation check: replacing `knn`'s distance order with insertion order
fails the hit@5 gate; dropping the hash check lets the staleness test
pass with an edited text, so the staleness test fails; counting a hit
as relevant without consulting `relevant_ids` fails the random-vector
test.

## Out of scope (follow-up)

A local store whose `vec_registry` names another model fails closed
with `VectorModelMismatch` once the default changes (by design: no
mixed-model vector space). There is no CLI rebuild command today; a
rebuild path is a separate plan. The offline suite is unaffected,
since it builds its own temporary store.

## Outcome handling

- Both gates pass: QA-002 and the D1 v2 precondition are met; the
  registry status change for QA-002 is an owner edit (registry
  discipline), and TP-035 implementation may proceed.
- A gate misses: no threshold is lowered and no label is changed to
  pass. The miss is recorded in the evaluation logbook and the D1 v2
  precondition stays unmet; TP-035 implementation stays blocked
  pending an owner decision (ADR-003 and risk R-04 name a QA-002 miss
  as a reopen trigger).
