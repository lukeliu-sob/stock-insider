## Driver

news-filtering-design.md D1 reserved v2 body fetching for tier-A
domains via the FR-015 path, activation pending an owner decision.
The owner asked to port the approach of a reference news-corpus
implementation into this project's news module under its governance,
and decided D5–D10 on 2026-10-26 (HK English local sources, a topical
bucket for current-affairs items, feedparser + BeautifulSoup, daily
cadence). This plan is documentation-first: the design note, the ADR
amendments and the D1 activation record precede any code; this plan
governs the implementation change set that follows approval.

Implementation precondition: D10 / D10a (owner, 2026-10-26). D1 v2
follows a QA-002 pass on the title corpus; TP-036 implemented QA-002
and it missed (E-011), and TP-037 found no query-side fix (E-012).
The owner accepted the residual for D1 v2 (D10a), so this plan's
approval is the only remaining gate. QA-002 stays a strict expected
failure (DE-17). (REQ-SI-FR-027, the topical
bucket row, was appended in registry v0.6.2 with this plan.)

Mutation check: removing the whitelist filter from selection fails
the never-fetched test; treating empty extraction as success fails
the short-extraction test; skipping quarantine writes fails the
quarantine-visibility test; advancing attempts without the cap fails
the unavailable test; counting transport failures as attempts fails
the outage test; removing the rss isolation boundary fails the sync
isolation test; admitting GDELT items to `topical` fails the
firehose test; dropping the topical exclusion from `pending_news`
fails the backlog test; removing the per-feed cap fails the overflow
test.

## Live probe (non-blocking; before first live run)

1. Every feed URL in design §4 other than SCMP responds 200 with a
   parseable feed; the URLs marked *(live-probe)* and the HK feeds
   without a URL are fixed here. A feed that fails is dropped from
   `RSS_FEEDS`, and its egress entry from the hunk.
2. Calibrate `EXTRACTION_TEMPLATES` selectors against live pages;
   bot-walled domains stay off `BODY_WHITELIST`.
3. For each body whitelist candidate, robots.txt allows the article
   paths and the site's terms permit fetching and local storage; a
   candidate that fails stays off `BODY_WHITELIST` (design D5).

## Fit-criteria mapping

- FR-003: symbol and macro buckets store RSS items only via token
  evidence (filter at ingestion unchanged); dedup keys apply across
  all sources; precision gate holds after the tier-list change.
- FR-027: (a)–(d) as in design §12, each mapped above.
- FR-015 (a): non-whitelisted body fetches fail closed (0 successes,
  logged); (b): fixture pages produce schema-valid bodies; failed
  extraction stores nothing.
- INV-003: every failure classified and reported; capped attempts
  become recorded unavailability, and only article-level failures
  count toward the cap; paused domains, topical overflow and
  unhealthy feeds visible in the run report.
- SEC-003: all new fetch hosts on the egress whitelist; denial is
  classified and writes nothing; the parsing libraries never open a
  connection.
