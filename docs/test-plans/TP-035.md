## Driver

news-filtering-design.md D1 reserved v2 body fetching for tier-A
domains via the FR-015 path, activation pending an owner decision.
The owner asked to port the approach of a reference news-corpus
implementation into this project's news module under its governance.
This plan is documentation-first: the design note, the ADR amendment
and the D1 activation record precede any code; this plan governs the
implementation change set that follows approval.

Approval precondition: design decision D10. D1 v2 follows a QA-002
pass on the title corpus; QA-002 is still conceptual. Approving this
plan requires either a passing QA-002 suite first or the owner's
recorded waiver.

Mutation check: removing the whitelist filter from selection fails
the never-fetched test; treating empty extraction as success fails
the short-extraction test; skipping quarantine writes fails the
quarantine-visibility test; advancing attempts without the cap fails
the unavailable test; counting transport failures as attempts fails
the outage test; removing the rss isolation boundary fails the sync
isolation test.

## Fit-criteria mapping

- FR-003: RSS items stored only via token evidence (filter at
  ingestion unchanged); dedup keys apply across all sources.
- FR-015 (a): non-whitelisted body fetches fail closed (0 successes,
  logged); (b): fixture pages produce schema-valid bodies; failed
  extraction stores nothing.
- INV-003: every failure classified and reported; capped attempts
  become recorded unavailability, and only article-level failures
  count toward the cap; paused domains and unhealthy feeds visible in
  the run report.
- SEC-003: all new fetch hosts on the egress whitelist; denial is
  classified and writes nothing.
