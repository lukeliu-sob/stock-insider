## Terms review (2026-10-26)

D5 admits a body domain only when its terms permit fetching and local
storage. The agent read what each site publishes; this is a reading,
not legal advice.

- **cnbc.com** (`/terms/`): "We prohibit downloadable (other than
  caching) ... copies of Content by a user", and the CNBC+, Pro and
  Investing Club supplements forbid scraping. The body track keeps
  copies, so CNBC fails D5 and is removed from `BODY_WHITELIST` (its
  template is removed too). Its feed stays: titles and summaries, the
  same depth GDELT already stores.
- **hongkongfp.com, news.gov.hk, rthk.hk**: no terms-of-use page was
  found (the obvious paths return 404 or an error page; the sites link
  only privacy or disclaimer pages without clauses on reproduction or
  automated access). robots.txt allows the article paths. They stay on
  the whitelist pending the owner's confirmation; no prohibiting clause
  was found.

## Implementation notes (deviations from the plan text)

1. **Source set follows the probe.** The CNBC top-news feed is added
   (tier-A, it supplies body candidates); MarketWatch, The Standard and
   China Daily HK are dropped, and their egress entries were never
   committed. Three HK domains join `GENERAL_NEWS_DOMAINS` (rthk.hk,
   hongkongfp.com, news.gov.hk); the FR-003 precision gate passes
   unchanged.
2. **News hosts are their own egress set.** `test_egress.py` pins the
   exact contents of `EGRESS_WHITELIST` and is the regression scope of
   REQ-SI-SEC-003, so the news hosts live in `NEWS_FETCH_HOSTS`, which
   `validate_egress_url` accepts alongside the whitelist. Matching and
   HTTPS-only are unchanged.
3. **A page seam in `http.py`.** `stdlib_fetch_page` returns bytes
   (feeds declare their own encoding), sends a fixed User-Agent, refuses
   bodies over 5 MB, and re-validates every redirect hop against the
   egress gate (the existing `stdlib_fetch` follows redirects
   unchecked; it is not changed here). `TransportError` gains an
   optional `status`.
4. **Templates are CSS selectors** (BeautifulSoup `select`), not
   (tag, class-substring) pairs.
5. **Body queue order and window.** The live run showed about 128 new
   whitelisted rows per day against the 30-article run cap, mostly
   topical. Keeping the owner's caps, the queue now takes evidence rows
   (symbol and macro buckets) before topical rows, newest first within
   each, and selects only rows published within 14 days; older waiting
   rows are reported as `stale` every run.
6. **One fetch per article.** Rows sharing a normalized URL across
   buckets are fetched once and updated together.
7. **Pacing follows requests that reached a host.** A fetch that failed
   before reaching one (network, egress) is not followed by a pause.
8. **Lookup indexes** in migration v8: body work queue
   `(body_status, published_at)`, `url_norm`, `published_at`
   (retention), `source`, and `news_quarantine(fetched_at)`; each hot
   query is pinned to its index by an EXPLAIN QUERY PLAN test.
9. **Offline isolation, found during implementation.** The offline
   conftest now blocks DNS and non-loopback connections and disables
   proxy discovery. On the owner's machine a system proxy on loopback
   had let three existing sync tests reach the live network; on CI,
   without a proxy, they did not.
