## Scope

Birth of `data/store` (the first authoritative-side module) plus the
`watch` CLI/slash surface. **In scope**:

1. SQLite store `data/stockinsider.db`: connection management (WAL),
   `schema_version` migration table, transactional forward-only
   migrations; a **newer schema is refused with an explicit version
   error** by older code (INV-003 semantics, memory-design §4).
2. Initial migration v1 defines **all** core tables once (avoiding
   migration churn while the schema is cheap to fix):
   `symbols` (symbol map: canonical symbol, exchange, official name,
   aliases JSON — Chinese aliases are the sole GOV-001 CJK exemption —
   verified flag, resolved_at), `watchlist` (active rows, 100 cap),
   `market_bars`, `fundamentals`, `news` + `news_quarantine`,
   `event_scores`, `fx_rates`, `sync_state` (cursors + daily call
   budget counters for the EODHD free tier), `sync_gaps` (gap queue).
   The vec0 embedding virtual table is deferred to a v2 migration in
   TP-012 (documented, not created here).
3. `SymbolResolver`: protocol + seeded built-in benchmark indices
   (HSI, HSTECH, S&P 500, Nasdaq-100) + an EODHD-search-backed
   implementation whose HTTP boundary is a injectable transport
   (offline tests mock it; live calls wait for TP-009 smoke).
4. Watchlist service: add / remove / list with the INV-004 gate — an
   add requires a **verified resolution record** and an explicit
   user-confirmation flag; the 101st active symbol raises an explicit
   cap error (GOV-004); additions enqueue the 5-year backfill gap
   record (queue only — backfill execution is TP-009).
5. Registry tools (agent surface): `watchlist_list` (read),
   `watchlist_add` (write, gated: args must carry the verified
   resolution id AND `user_confirmed: true`; the tool itself refuses
   otherwise — deterministic backstop behind the prompt-level
   confirmation flow), `watchlist_remove` (write). The conversational
   confirmation flow is instructed in `prompts/identity.md` (one added
   paragraph; GOV-003 applies — eval replay per prompt change).
6. CLI `watch` subcommand (list / add / remove) + `/watch` slash
   command, both via the data facade.

**Not in scope**: any network adapter execution (EODHD live calls —
TP-009), fundamentals/news ingestion, embeddings, computation, FX.
`data/ingest`, `data/compute` gain only their package skeletons.

## Negative tests (mandatory, R7)

Three adversarial classes pin INV-004 end-to-end (fabricated ticker /
missing confirmation flag / exchange collision) — the suite's
fit-criterion demand of **0 additions** is asserted literally
(`watchlist` row count unchanged). Structural negative: newer-schema
refusal.

## Boundary cases (R8)

Watchlist cap: exactly 100 (succeeds) and 101 (explicit error). Alias
matching boundary for resolver stubs is deferred (live resolver is
TP-009+).

## Fit-criteria mapping

- **FR-004 (a,b,c)**: mocked-resolver add-with-confirm, not-found
  report, fabricated-ticker 0-additions cover clauses (a), (b), (c).
- **INV-004 (zero tolerance)**: the three adversarial classes above
  assert 0 additions without verified resolution + confirmation;
  exchange collision shows presentation-not-selection.
- **GOV-004**: cap boundary pair.

## Amendment 2 (2026-09-18) — BD-009 fix: env-file key + live transport wiring

Live use found two stacked defects in the delivered resolver: (1) the
EODHD_API_KEY was read only from real environment variables — the
local dotenv file (SEC-001-sanctioned) was ignored; (2) the stdlib
live transport was never wired by default, so even a correctly set
key raised the misleading "set EODHD_API_KEY" error. Fix: shared/envfile
(born under ADR-004's governance; real env wins, file path via
STOCKINSIDER_ENV_FILE override) + resolver default wiring (key in env
OR file -> stdlib transport) + is_live() probe + CLI-test env-file
isolation. New suite: test_envfile.py (6 tests). Recorded as BD-009.
