## Driver

Owner live session, 2026-10-02, in the terminal UI (`--ui tui`): `/sync`
and `/sync run` both answered

```
error: unknown argument(s) ['user_confirmed'] for tool 'sync.run'; allowed: []
```

Reproduced offline against the real registry. Every human-typed slash
write command fails in the same way, before any data-layer call:

| Slash command | Result before TP-022 |
|---|---|
| `/sync`, `/sync run` | `unknown argument(s) ['user_confirmed'] for tool 'sync.run'; allowed: []` |
| `/watch add <mention>`, then `y` | `... for tool 'watchlist.add'; allowed: ['canonical_symbol']` |
| `/watch remove <symbol>`, then `y` | `... for tool 'watchlist.remove'; allowed: ['canonical_symbol']` |

Root cause: TP-017 PR-2 (H3, PR #51, 2026-09-29) removed the
model-fillable `user_confirmed` boolean from every write tool spec, and
the registry rejects arguments a spec does not declare (fail-closed).
The three slash handlers in `agent/repl.py` (`_cmd_sync`, and
`_cmd_watch` for add and remove) still sent `"user_confirmed": True`.

Unaffected paths:

- the confirmed-token path (`confirm <token>`), which replays the
  model's own arguments;
- the CLI subcommands `sync` and `watch add/remove`, which call the data
  store directly.

No test executed these three paths. The `_cmd_sync` tests cover
`status` only, and the TP-021 UI tests cancel `/watch add` before it
executes.

No side effect occurred: every call was rejected at argument validation.
No sync ran, no call budget was spent, and the watchlist did not change.

## Fix

Each slash call sends exactly its tool's arguments: none for `sync.run`,
`canonical_symbol` for `watchlist.add` and `watchlist.remove`.

The write gate is unchanged: `allow_write=True`. Only these human-typed
commands set it, and for `/watch` only after the human answers the
`[y/N]` prompt (blueprint §9.1; ADR-005 Am3). The model's path still
never sets `allow_write`.

The stale `_cmd_watch` docstring, which still names the removed boolean
as the gate, is corrected.

## Planned tests

All in `test/offline/test_tp022_slash_writes.py`. The tests use the real
dispatch and the real registry over a fake data store that records

| Test | Verifies | Kind | Notes |

## Negative tests (mandatory, R7)

- `test_slash_watch_writes_need_a_yes`: any answer but a yes executes
  nothing (INV-004 human confirmation).
- `test_unknown_sync_action_still_errors`: an unknown action is
  reported, never guessed.
- `test_slash_tool_calls_match_tool_specs` fails if any slash call
  carries an argument the spec does not declare. That covers this
  regression and any later spec change that misses a caller.
- Kept green (regression scope): the model still cannot write through a
  boolean (`test_confirm_tokens.py::test_model_cannot_execute_write_via_boolean`).

## Boundary cases (R8)

The `[y/N]` answer is trimmed and case-folded by the existing handler.

- Accepted: `y`, `Y` and ` yes `.
- Declined: `ye`, `yes please`, `q` and the empty answer.

## Fit-criteria mapping

- REQ-SI-FR-001: sync runs from the REPL entry
  (`test_slash_sync_runs_after_the_command`).
- REQ-SI-FR-004 and REQ-SI-INV-004: watchlist add and remove execute only
  after the human's yes (the positive test and the negative test).
- REQ-SI-FR-013: the slash command and the CLI subcommand are the same
  verb again (the REPL entry now works like `stockinsider sync` and
  `stockinsider watch`); the structural test guards the drift class.
