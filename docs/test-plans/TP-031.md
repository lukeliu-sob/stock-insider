## Driver

TP-029 marks a turn interrupted by Ctrl+C. Two other exits also end a turn without an answer, and their questions still replayed on the next turn:

- The tool-iteration cap. `_run_turn` appends an `error` event with `kind: "iteration-cap"` and returns (`agent/loop.py`, the iteration-cap branch).
- A `ProviderError` that escapes the turn. Nothing in the loop catches it, so it propagates to the REPL, which prints `error: ...`.

P-17 says a turn that never reaches its post-check is recorded as `incomplete` and left out of context. Both exits above never reach a post-check.

## Fix

1. `agent/loop.py`: a `_mark_incomplete` helper appends `turn-incomplete` for the open turn and closes it. `run_turn` calls it when a `ProviderError` escapes, as it already does for `KeyboardInterrupt`. The error still propagates unchanged.
2. `agent/loop.py`: the iteration-cap branch calls `_mark_incomplete` after its `error` event. Its return value is unchanged.
3. `agent/loop.py`: `_history_messages` is unchanged. The rule from ADR-001 Am2 (a turn with a marker and no answer is left out) already covers these turns.
4. `agent/repl.py`: the transcript line for the marker uses generic wording ("no answer recorded"), because the marker no longer means only an interruption.

## Scope

In scope (files): `src/stockinsider/agent/loop.py`, `src/stockinsider/agent/repl.py` (one string), `test/offline/test_tp031_no_answer_turns.py` (new), `test/offline/test_tp029_incomplete_turns.py` (see Supersession), `docs/architecture/adr/004-shared-foundation.md` (Amendment 6), `docs/architecture/adr/001-runtime-architecture-and-context-engineering.md` (Amendment 3), `docs/debt-register.md`, `docs/ai-use-log.yaml`.

Explicitly NOT changed: `shared/` (the kind is unchanged), `agent/guardrail*`, `agent/registry*`, the post-check, `prompts/`, the aborted-session refusal (it returns before any user message is written, so there is nothing to mark), and the plain REPL's error text.

Residual, not closed: a hard crash (process killed, power loss) runs no handler and writes no marker. Other unexpected exceptions (defects) propagate without a marker, as before. They are not turn outcomes, and recording them silently as ordinary incomplete turns would hide the defect. Marking them would be a separate decision.

## Supersession of TP-029 tests

- `test_provider_error_is_not_marked` (TP-029's scope pin) is removed. `test_provider_error_marks_turn_incomplete` in TP-031 replaces it. The scope change is this TP's decision, recorded here, not a silent edit to an old expectation.
- `test_transcript_shows_incomplete_turn` changes its asserted text to the generic wording.
