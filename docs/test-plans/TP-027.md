## Driver

PR #61's CI "regression" job failed: `test/offline/test_ingest_news_sync.py::test_store_filter_dedup_and_quarantine` — `assert symbol_query["kept_new"] == 2` got `3`. The same PR's content (main at `4ea1c64`, plus one unrelated file) passed this exact test in CI when PR #60 merged on 2026-10-02 (`gh run list --branch main`, conclusion `success`, headSha `4ea1c64...`). Unrelated to PR #61's change (`agent/guardrail_claims.py`) or to any debt-register item; confirmed independently by `git stash`-ing PR #61's diff and re-running against the unmodified tree, where it fails identically.

Reproduced offline (real helpers, not a mock): `kept_new=3, dups=1, quarantined=1` (expected `2, 2, 1`). The extra "kept" row is `"Tencent Holdings buys back shares now"` (`key_b` in the test), which should have deduped against `"Tencent Holdings buys back shares"` (`key_a`) via the near-title similarity gate.

**Root cause**: `_article()`'s default `seendate="20260918T090000Z"` (`test_ingest_news_sync.py:59`) is a fixed absolute date. `run_news_sync()` accepts an explicit `now:` parameter (`news.py:412`) but the test never passes one, so it defaults to real wall-clock time. The near-title dedup gate ("Key B: title token-set similarity", `news.py:341`) only applies inside a rolling window: `dup_cutoff = now - timedelta(days=DUP_WINDOW_DAYS)`, `DUP_WINDOW_DAYS = 14` (`news.py:63, 272`). `2026-09-18 + 14 days = 2026-10-02` — the test passed through 2026-10-02 (the boundary day, inclusive) and was mathematically guaranteed to start failing on 2026-10-03, independent of any code change: a test fixture tied to the calendar rather than to a controlled clock.

**Classification**: test-fixture time bomb (uses real wall-clock time where a frozen reference was needed); CI-blocking, since the "regression" gate requires the full suite green with no allowlist for a pre-existing-but-now-failing case. From 2026-10-03 onward this blocks every PR's regression gate, not only #61's, until fixed.

## Fix

Pass an explicit `now=` to the one `run_news_sync(...)` call in `test_store_filter_dedup_and_quarantine`, fixed well inside the 14-day dedup window relative to the fixture's `20260918T090000Z` seendate (not at the edge, so the fix itself does not become a new boundary bomb). The test stops depending on wall-clock time; every other test in the file already either passes its own `now=` or does not exercise the near-title gate, so no other test is affected.
