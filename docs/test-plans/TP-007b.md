## Amendment (2026-09-17) — in-REPL /resume semantics fix

Live use found the in-REPL /resume binding-swap unintuitive: the
current session was left active (orphaned) with no way to close it
from the REPL. Corrected semantics (owner ruling, option A): /resume
resolves the target first (closed sessions only), refuses self-resume,
closes the current session cleanly, then binds the target; both REPL
entries print a `resume with: stockinsider resume <id>` hint on exit.
Covered by two new tests in test_resume.py. Recorded as BD-007; the
same round logs BD-008 (default model name rejected by the live
endpoint, fixed in PR #10).
